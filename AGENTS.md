# Easy Boost — инструкции для агентов

Приложение-репетитор для подготовки к ЕГЭ по английскому языку. Node.js + Express, PostgreSQL,
frontend без фреймворка в `public/`. Готовится к ограниченному production-запуску.

## Единственный источник требований

`../../ТЗ_подготовка_Easy_Boost_к_продакшену.md` (вне репозитория, на рабочем столе владельца) —
полное ТЗ подготовки к production. Выполненные пункты зачёркнуты и отмечены `✅`. Любое утверждение
о готовности проверяется по нему, а не по памяти.

## Как устроен репозиторий

| Каталог | Что внутри |
|---|---|
| `server.js` | конфигурация, общие middleware, завершение работы — и ничего больше |
| `middleware/`, `services/`, `routes/` | авторизация, контроль доступа, Telegram, подписки, маршруты |
| `ai/` | реестр операций, промпты, схемы, контроль провайдеров |
| `public/` | frontend: `app.js`, `router.js`, `store.js`, `components.js`, `modules/*.js` |
| `docs/` | схема БД, AI-операции, мониторинг, приватность, восстановление, OpenAPI |
| `docs/adr/` | зафиксированные архитектурные решения |
| `docs/agents/` | конвенции для агентов, в том числе трекер задач |
| `test/`, `e2e/` | 261 unit/integration-тест и Playwright-сценарии |
| `quality/` | эталонный набор для методической проверки ИИ (раздел 11 ТЗ) и раннер прогона |

## Проверка качества ИИ

Команды `npm run quality:*` — это не только эталонный набор, но и раннер: он прогоняет работы через
ту же цепочку вызова провайдера, что работает у учеников, пишет журнал и сворачивает его в метрики
раздела 11 ТЗ. Порядок команд от начала до конца, ключи, куда что оседает и **чего этот путь
измерить не может** — в разделе «Порядок прогона: от условия до отчёта» в
[quality/README.md](quality/README.md). Настоящий прогон платный: его запускает владелец, а не
агент, и до него пункты раздела 11 ТЗ выполненными не считаются.

## Трекер задач

Локальный markdown. Правила — в [docs/agents/issue-tracker.md](docs/agents/issue-tracker.md).

## Обязательные проверки перед коммитом

```bash
npm run lint && npm run check && npm test
```

E2E и производительность запускаются отдельно: `npm run test:e2e`, `npm run test:e2e:performance`.

## Правила, которые нельзя нарушать

- **Секреты**: только имена переменных окружения. Значения живут в `.env`, который в `.gitignore`.
  Секрет никогда не попадает в код, тикет, промпт, коммит или отчёт.
- **Деплой** staging и production — действие владельца, а не агента, в любом режиме работы.
- **API**: продуктовые маршруты живут под `/api/v1/`. Health и metrics остаются без версии.
- **ИИ**: клиент не передаёт системные промпты. Все операции описаны в `ai/operations.js`.
- **Совместимость**: 261 существующий тест — часть контракта. Тест не удаляется ради зелёной сборки.
