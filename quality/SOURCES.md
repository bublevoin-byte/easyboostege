# Источники эталонного набора (раздел 11 ТЗ)

Раздел 11 требует набор работ с оценками квалифицированного проверяющего. Ниже — что найдено,
что из этого пригодно машинно и чего не хватает. Проверено 26 июля 2026 года.

## Основной источник

**Методические материалы для председателей и членов предметных комиссий субъектов РФ**
(ФИПИ, Рособрнадзор). Авторы — М. В. Вербицкая, И. А. Басова, К. С. Махмурян, Ю. Б. Курасовская,
то есть федеральная комиссия разработчиков ЕГЭ. Публикуются ежегодно, свободно доступны.

Скачать все восемь документов за 2023–2026 годы:

```bash
npm run quality:sources
```

Файлы попадают в `quality/sources/` и не коммитятся: это материалы ФИПИ, а не наш код.
Текст извлекается `pdftotext -enc UTF-8 -layout` — без `-enc UTF-8` кириллица теряется.

| Документ | Что внутри |
|---|---|
| `angl_yaz_pch_mr_ege_<год>.pdf` | письменная часть: задания 37 и 38, разобранные работы с побалльным комментарием эксперта по каждому критерию и дополнительными схемами оценивания |
| `angl_yaz_uch_mr_ege_<год>.pdf` | устная часть: критерии всех четырёх заданий, скрипты ответов, комментарии с баллами |

Эти оценки выставлены не одним преподавателем, а авторами критериев ЕГЭ, поэтому как эталон
они сильнее, чем требует пункт 11.1.

## Что получается собрать

| Требование 11.1 | Нужно | Доступно у ФИПИ | Состояние |
|---|---:|---:|---|
| задание 37 | 20 | 13 уникальных за 2023–2026 | **заготовки собраны:** `npm run quality:stubs`; тексты работ — сканы бланков, нужен ручной набор |
| задание 38 | 30 | 9 уникальных за 2023–2026 | то же; до 30 работ далеко не хватает |
| устная часть, задание 3 | 10–15 | 144 оценённых ответа, 24 полных скрипта, 14 уникальных | **собрано:** `npm run quality:extract` → `speaking-3-fipi.json` |
| устная часть, задания 1, 2, 4 | по 10–15 | практикум построен на аудиозаписях | скриптов в открытых документах нет |

Разбор одной работы устроен так: условие задания, скан бланка, таблица аспектов и текстовый
комментарий вида «Аспект 3 не раскрыт», «ИТОГОВЫЙ БАЛЛ (максимальный балл – 2)». Баллы и
комментарии извлекаются текстом; сам ответ ученика — изображение.

## Чего не хватает и как закрывать

1. **Тексты работ 37 и 38.** Сканы придётся перенабрать вручную: это рукописные бланки, OCR по
   ним ненадёжен. Оценки и комментарии при этом берутся из текста документа, поэтому ручная
   работа — только перенос ответа ученика.
2. **Добор до 30 работ задания 38** и **устные задания 1, 2, 4.** Открытых источников с
   оценёнными работами в текстовом виде найти не удалось: сайты подготовки публикуют шаблоны и
   разборы, но не работы с побалльной оценкой эксперта. Здесь нужен либо свой преподаватель,
   либо региональные статистико-аналитические отчёты (ниже).
3. **Спорные случаи и prompt injection.** Пункт 11.1 требует работы с попыткой внедрить
   инструкцию для ИИ — таких в материалах ЕГЭ нет по определению. Эти записи составляются нами;
   образцы уже есть в `engineering-smoke.json`.

## Дополнительные источники

- [Аналитические и методические материалы ФИПИ](https://fipi.ru/ege/analiticheskie-i-metodicheskie-materialy) —
  методические рекомендации для учителей по итогам анализа типичных ошибок, ежегодно.
- Региональные статистико-аналитические отчёты о результатах ЕГЭ, например
  [Костромская область, 2025](https://koiro.edu.ru/wp-content/uploads/2025/10/SAO-11-angl.yaz-2025.pdf) и
  [Республика Башкортостан, 2025](https://rcoi02.ru/sao11/files/SAO_EGE_ENG_2025.pdf) —
  содержат методический анализ по критериям, иногда с примерами работ.
- [Открытый банк заданий ЕГЭ](https://fipi.ru/ege/otkrytyy-bank-zadaniy-ege) — сами задания без
  ученических работ; полезен как источник условий для новых записей набора.

## Правовая заметка

Документы опубликованы ФИПИ открыто и предназначены для экспертов и учителей. Использование их
как внутреннего эталона для проверки нашей модели выглядит обоснованным, но это не юридическое
заключение: решение о допустимости принимает владелец проекта. Поэтому PDF не хранятся в
репозитории, а скачиваются скриптом; в `quality/release.json` попадают только анонимные тексты
работ и баллы, без выходных данных и вёрстки источника.

## Формат записей

Структура — та же, что у `engineering-smoke.json`. Для работ из материалов ФИПИ:

```json
{
  "id": "w37-fipi-2026-4325",
  "operation": "writing_37",
  "tags": ["strong", "fipi-2026"],
  "answer": "<перенабранный текст работы>",
  "human": {
    "total": 6,
    "criteria": { "task": 2, "organisation": 2, "language": 2 },
    "reviewer": "fipi-2026-expert-manual"
  },
  "expectedCriticalErrors": [],
  "aiRuns": []
}
```

`human.reviewer` фиксирует происхождение оценки. Персональных данных в материалах нет: работы
обезличены и обозначены только номером бланка.
