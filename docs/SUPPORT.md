# Инструкция поддержки

1. Запросить у пользователя время ошибки, экран и безопасный `requestId`; не запрашивать пароль, cookie или API-ключ.
2. Проверить публичный сайт и `/health/ready`.
3. Проверить состояние контейнеров и структурированные логи по `requestId`.
4. Для ошибки входа проверить Telegram bot и срок кода; для подписки — серверный статус пользователя; для ИИ — provider code и rate limit.
5. Не исправлять пользовательский прогресс вручную без резервной копии и подтверждения владельца.
6. Критический инцидент: остановить rollout, сохранить логи, использовать documented rollback, затем оформить причину и предотвращение повторения.

## Reading 2.0

- Если отчёт не загрузился из-за сети, убедиться, что интерфейс показывает «Статус Premium не изменён» и не оставляет прежние расширенные данные; затем повторить запрос после восстановления сети.
- Если Premium был отозван или истёк, проверить актуальные `subscriptions` и `voice_tutor` entitlement. Сервер должен ответить `READING_PREMIUM_REQUIRED`, клиент — сразу показать полезный Base-отчёт и не открывать новую Voice-сессию.
- Не восстанавливать отчёт вручную: он заново детерминированно строится из завершённых owner-bound canonical Reading attempts. Проверить наличие обеих строк gist/detail у полного раздела и revision каталога; неполные/legacy/technical строки намеренно не учитываются.
- Если cached Reading открывается, но новая тренировка не стартует, проверить fresh `/api/v1/me` и `Cache-Control: no-store`: inactive должен открыть общий экран «Нужен активный доступ», а сеть/timeout — «Не удалось проверить доступ». Локальный каталог и поздний ответ после adaptive timeout не должны обходить этот gate.
