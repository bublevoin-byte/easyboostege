# 02 — Провести локальный аудит экспериментального релиза

Status: ready-for-agent
Blocked by: 01
Spec: .scratch/experimental-release-profile/spec.md#testing-decisions

## Что сделать

На зафиксированном кандидате выполнить все доступные бесплатные локальные проверки, составить отчёт с доказательствами и обновить §24 и оба процента ТЗ только там, где критерий действительно подтверждён.

## Границы

- Входит: lint/check/tests, доступные browser E2E и performance, security scans, quality-runner, анализ известных дефектов, схем ИИ-ответов и релизных критериев, отчёт `docs/EXPERIMENTAL_RELEASE_AUDIT.md`.
- Не входит: сеть и платные ИИ-вызовы, установка отсутствующих компонентов, push/deploy, staging soak, физические устройства, секреты, внешние оповещения, юридическая проверка и второй сервер.

## Definition of Done

- [ ] Отчёт фиксирует дату, исходный commit, все команды и точные результаты без секретных значений.
- [ ] Обязательные локальные тесты, lint и check проходят; недоступные проверки честно записаны как ограничения.
- [ ] Отдельно подтверждено или опровергнуто отсутствие известных critical/high дефектов.
- [ ] Отдельно подтверждено или опровергнуто применение строгой схемы ко всем ИИ-операциям.
- [ ] Критерии §24 меняются только на основании записанного доказательства.
- [ ] Критерий 1 при наличии доказательств засчитывается только для экспериментального профиля, не для строгого.
- [ ] Критерий 12 и §11 остаются явно открытыми в строгом профиле и исключёнными, а не выполненными, в экспериментальном.
- [ ] Новый staging soak не объявлен начатым до разрешённого деплоя текущего кандидата.
- [ ] Итоговые строгий и экспериментальный расчёты воспроизводятся командами readiness CLI.
- [ ] Проведён двухосевой review относительно коммита тикета 01; замечания устранены или обоснованы.
- [ ] Один локальный коммит на тикет; рабочее дерево чистое.
