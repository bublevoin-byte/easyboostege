# 02 — Построить доменный контракт Reading 2.0

Status: ready-for-agent
Blocked by: 01
Spec: `.scratch/reading-2-pilot/spec.md#глубокий-модуль-и-границы-ответственности`

## Что сделать

Создать глубокий Reading API для валидации каталога, owner-bound истории, умного выбора комплектов, полного раздела, scoring/review и миграции старого состояния. Экран не должен знать алгоритм ротации и внутреннюю схему каталога.

## Границы

- Входит контракт каталога `reading-pilot-v1`, негативные валидатор-тесты и совместимый адаптер старых данных.
- Входит bounded history, unseen/due/weak/old selection и запрет мгновенного повтора.
- Входит официальное оценивание 3/2/7 и полного 12, отдельная диагностическая точность 7/6/7, evidence slices и сериализация незавершённой попытки.
- Не входит написание 60 контентных комплектов и новая отрисовка экрана.

## Файлы

- новый `public/reading-catalog-contract.js`
- `public/modules/reading.js`
- новые/существующие frontend Reading tests

## Definition of Done

- [ ] Публичный API скрывает validation/selection/history/scoring/review.
- [ ] Негативные тесты отклоняют все перечисленные в спецификации нарушения.
- [ ] Ротация детерминированна и не повторяет последний комплект при наличии альтернативы.
- [ ] Старое состояние Reading нормализуется без потери суммарного прогресса.
- [ ] Целевые тесты, `npm run lint`, `npm run check`, `npm test` проходят.
- [ ] Один коммит на тикет.
