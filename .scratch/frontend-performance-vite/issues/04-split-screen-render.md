# 04 — Убрать синхронную отрисовку экрана из обработчика клика

Status: ready-for-agent
Blocked by: 03
Spec: .scratch/frontend-performance-vite/spec.md#42-ленивая-загрузка-экранов

## Что сделать

Довести INP до бюджета 200 мс. Замер показывает 224 мс на одном взаимодействии против 112 мс у
следующего за ним: переход на экран предметного модуля выполняет всю отрисовку внутри обработчика
клика, и браузер не может отдать кадр, пока она не закончится.

Разделить работу: переключение экрана и первый кадр происходят сразу, наполнение данными — в
следующем кадре. Ученик видит отклик мгновенно, содержимое появляется кадром позже.

## Границы

**Входит:**

- `router.js`: переключение видимости экрана отделено от его наполнения.
- Модули экранов: тяжёлая отрисовка (списки слов, наборы вопросов, тексты) выносится из
  синхронного пути обработчика.
- Замер после изменения: `npm run test:e2e:performance` должен показать INP ≤ 200 мс.

**Не входит:**

- Изменение бюджетов в `e2e/performance.test.js` — бюджеты раздела 19 не трогаются никогда.
- Вынос данных в JSON — тикет 05.
- Косметика интерфейса. Ученик не должен заметить ничего, кроме скорости.

## Файлы

- `public/router.js`
- `public/screens/*.js`
- `public/components.js` — если нужен общий помощник «отрисовать в следующем кадре»
