# 03 — Ленивая загрузка экранов через динамический import()

Status: ready-for-agent
Blocked by: 02
Spec: .scratch/frontend-performance-vite/spec.md#42-ленивая-загрузка-экранов

## Что сделать

Сделать так, чтобы код предметного экрана приезжал по требованию, при первом переходе на него, а не
при старте приложения. Первая загрузка тянет только оболочку: маршрутизацию, хранилище, общие
компоненты, авторизацию, синхронизацию и главный экран.

`public/app.js` весит 289 КБ и содержит код всех экранов сразу. Его нужно разрезать: код каждого
экрана переезжает в свой модуль, который `router.js` загружает динамическим `import()`.

## Границы

**Входит:**

- Вынести из `app.js` код экранов девяти предметных модулей: слова, грамматика, чтение,
  аудирование, письмо, говорение, экзамен, прогресс, профиль.
- `router.js`: `tab(id)` становится асинхронным по сути — сначала грузит чанк экрана, затем
  показывает. Уже загруженный экран не ждёт ничего.
- Состояние загрузки из `components.js` показывается, только если чанк не пришёл за 100 мс:
  на быстром соединении ученик не должен видеть мигание.
- Ошибка загрузки чанка даёт типизированное состояние с повторной попыткой, а не пустой экран.
  Офлайн-поведение — как у остальных операций раздела 6.2.
- `public/service-worker.js`: чанки экранов кэшируются при первой загрузке, чтобы офлайн-запуск
  открывал уже виденные экраны. `/api/` из кэша по-прежнему не отвечает.

**Не входит:**

- Разделение синхронной отрисовки на кадры — тикет 04.
- Вынос учебных данных в JSON — тикет 05.
- Vite — тикет 06. Здесь используется только нативный `import()`.

## Файлы

- `public/app.js` — уменьшается, остаётся оболочкой
- `public/screens/*.js` — новые модули экранов
- `public/router.js`
- `public/components.js` — состояние загрузки экрана, если нужного ещё нет
- `public/service-worker.js`
- `package.json` — список файлов в `npm run check`
- `test/*.test.js` — тесты экранов следуют за переехавшим кодом

## Definition of Done

- [ ] При первой загрузке приложения ни один из девяти предметных экранов не запрашивается.
- [ ] Первый переход на экран даёт отдельный сетевой запрос за его чанком, повторный — нет.
- [ ] Медленная или неудачная загрузка чанка даёт видимое состояние с повторной попыткой.
- [ ] Офлайн-запуск открывает ранее виденные экраны, а не страницу-заглушку.
- [ ] `npm test` — 260 проходят, 1 пропущен.
- [ ] `npm run lint`, `npm run check`, `npm run build:frontend` проходят.
- [ ] `npm run test:e2e` и профили `firefox`, `android`, `iphone-webkit` проходят.
- [ ] Один коммит.
