## 1. Зачем

Прогон подготовки к production на 29 июля 2026 года: закрыто 425 из 478 проверяемых требований,

## 3. Причина

`public/index.html` подключает двадцать классических скриптов через `<script defer>`:

```
api, auth, sync, store, components, router, learning,
modules/{words,grammar,reading,listening,writing,speaking,exam,progress,profile},
app, privacy, tts, pwa
```

Все они обмениваются данными через глобальные имена. Следствия:

- `public/app.js` весит 289 КБ и содержит код всех экранов сразу. Отложить его нельзя: он
  подключён статически.
- Первый экран ждёт разбора всего JavaScript приложения, включая экраны, которые ученик, возможно,
  не откроет за сессию.
- Переход на экран модуля выполняет всю отрисовку в одном синхронном обработчике — отсюда 224 мс.
- Ленивой загрузки нет в принципе: классический скрипт нельзя импортировать по требованию.

## 4. Целевое состояние

### 4.1. Модульность

`public/index.html` подключает **одну** точку входа `<script type="module" src="/main.js">`.
Всё остальное — ES-модули с явными `export`. Имена, которые нужны инлайновым обработчикам разметки
и E2E-сценариям, привязываются к `window` явно и в одном месте, а не появляются там по побочному
эффекту объявления функции.

Инлайновых обработчиков в разметке 22 штуки, они ссылаются на 13 функций:
`tab`, `nav`, `setTask`, `r_add`, `countWords`, `wSpeak`, `tgClick`, `startDemo`, `openLearn`,
`logout`, `checkWriting`, плюс `initWords` и `curTask`, которые вызывает `router.js`.
E2E дополнительно использует `window.tab`.

### 4.2. Ленивая загрузка экранов

Код экрана загружается динамическим `import()` при первом переходе на него. Первая загрузка
приложения тянет только оболочку: маршрутизацию, хранилище, общие компоненты, авторизацию,
синхронизацию и главный экран.

Переход показывает состояние загрузки из `components.js`, если чанк не пришёл за 100 мс, и только
затем отрисовывает экран. Повторный переход на уже загруженный экран не ждёт ничего.

Отрисовка экрана разбивается так, чтобы обработчик клика не выполнял всю работу синхронно:
переключение экрана и первый кадр — сразу, наполнение данными — в следующем кадре.

### 4.3. Учебный контент

Учебные данные (словари, тексты для чтения, наборы вопросов грамматики, диалоги аудирования,
банк тем письма) выносятся из кода в JSON и загружаются вместе с чанком своего экрана, а не при
старте приложения.

### 4.4. Сборка

Vite собирает `public/` в `dist/public`: бандлинг, минификация, хешированные имена файлов,
автоматическое разделение динамических импортов на чанки.

`public/` остаётся каталогом исходников — все существующие тесты читают именно эти файлы.
Сервер отдаёт `dist/public`, если каталог существует, иначе `public/`. CSP считает хеши инлайновых
скриптов по тому же `index.html`, который реально отдаётся.

## 5. Критерии приёмки

1. `npm run test:e2e:performance` завершается успешно: INP ≤ 200 мс, LCP ≤ 2500 мс, CLS ≤ 0.1,
   индикатор проверки ИИ ≤ 200 мс.
2. JavaScript первой загрузки — не более 150 КБ по сети против нынешних 350 КБ.
3. Каждый из девяти предметных экранов приезжает отдельным запросом при первом переходе на него,
   и это видно в списке сетевых запросов.
4. `npm test` — все 261 тест в прежнем состоянии: 260 проходят, 1 пропущен. Ни один тест не удалён
   и не ослаблен ради зелёной сборки.
5. `npm run lint`, `npm run check`, `npm run build:frontend` проходят.
6. `npm run test:e2e` и профили `firefox`, `android`, `iphone-webkit` проходят.
7. Приложение работает офлайн ровно как раньше: service worker отдаёт оболочку и уже загруженные
   чанки, `/api/` из кэша по-прежнему не отвечает.
8. CSP не ослаблена: `script-src` остаётся `'self'` плюс хеши инлайновых скриптов.
9. Пункты разделов 4.1, 4.2, 20.1, 20.2 либо подтверждены фактом и отмечены `✅`, либо признаны
   неприменимыми с записанной причиной.

## 6. Границы

**Входит:** перевод на ES-модули, ленивая загрузка экранов, вынос учебного контента, сборка Vite,
обновление service worker, `build-frontend.js`, отдачи статики сервером и документации,
проверка и разметка разделов 4 и 20, обновление статуса в ТЗ.

**Не входит:**

- Миграция на React. Зафиксирована как направление в `docs/adr/0001-frontend-build-and-framework.md`,
  выполняется отдельным этапом.
- Раздел 11 — методическая проверка качества ИИ. Заблокирован набором работ.
- Ротация ранее использовавшихся секретов (раздел 14) — действие владельца.
- Приёмка на живых iPhone Safari и Android Chrome (раздел 18.4) — действие владельца.
- Деплой на staging и production. Прогон заканчивается коммитами в ветку `production-hardening`.
- Изменение поведения приложения. Ученик не должен заметить ничего, кроме скорости.
