# 10 — Выбор модели ключом и настоящая причина отказа в журнале

Status: done
Blocked by: 05

## Что сделать

Первый настоящий прогон 31 июля 2026 года вскрыл в раннере два недостатка. Оба мешают
следующему шагу — сравнить две модели прогоном по набору и выбрать ту, что оценивает работы
учеников.

**Модель нельзя выбрать командой.** Она берётся из `XAI_MODEL` / `GROQ_MODEL` в `.env`, а имя
журнала по умолчанию выводится из набора и провайдера. Значит два прогона разных моделей лягут
в один файл — и второй будет **молча пропущен**: возобновление опознаёт пару «работа + номер
прогона», модель в неё не входит. Прогон, за который заплатили, не состоится, а раннер отчитается,
что всё уже сделано.

**Журнал теряет причину отказа.** Все пять неудачных вызовов записаны как `AI_UNAVAILABLE` —
обёртка `runProviderFallback` вокруг настоящей ошибки. Настоящей была отсечка по таймауту:
`grok-4.5` отвечает 118 секунд при бюджете 45. Установить это удалось только по полю `durationMs`,
совпавшему с бюджетом до миллисекунды. `runProviderFallback` кладёт в ошибку `cause`,
`fallbackReason`, `provider` и `model` — раннер их просто не записывает.

## Границы

Входит:

- Ключ `--model=<id>`, переопределяющий модель провайдера на весь прогон. Без ключа — как сейчас,
  из `.env`.
- Имя журнала по умолчанию включает модель: два прогона разных моделей расходятся по разным
  файлам сами, без внимательности запускающего.
- В строку журнала пишется причина отказа: `cause` и `fallbackReason` из ошибки, а также
  применённые к вызову `timeoutMs` и `maxTokens`. Отсечка по таймауту должна читаться из записи
  прямо, без сопоставления длительностей.
- Модель печатается в шапке прогона и в итоге — рядом с числом вызовов и оценкой стоимости.

Не входит:

- Изменение поведения приложения. `ai/provider-client.js` правится только если без этого не
  передать модель; бюджеты `ai/operations.js`, тексты ошибок и логирование в `ai_requests`
  остаются как есть. Выбор модели для учеников — решение владельца, а не следствие этого тикета.
- Повторная попытка при таймауте. Отказ записывается, прогон идёт дальше — это уже так и работает.
- Перенос уже записанного журнала `writing-fipi-stubs-grok.jsonl` с пятью отказами. Он остаётся
  как есть: это свидетельство, а не мусор.

## Файлы

- `scripts/ai-quality-run.js` — ключ `--model`, имя журнала, причина отказа в записи.
- `ai/provider-client.js` — только если иначе модель не передать; поведение приложения не менять.
- `package.json` — если понадобится.
- `test/ai-quality-run.test.js` — новые случаи: `--model` доходит до тела запроса; журналы разных
  моделей не совпадают по имени; отказ несёт причину и применённый таймаут.
