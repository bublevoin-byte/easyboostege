# 11 — Отчёт считает метрики по одной модели, а не по всем сразу

Status: done
Blocked by: 06
Spec: .scratch/ai-quality-runner/spec.md#слияние-scriptsmerge-quality-runsjs

## Что сделать

Владелец сравнивает две модели прогоном по набору, чтобы выбрать ту, что будет оценивать работы
учеников. Слияние (тикет 06) кладёт прогоны обеих в один набор и правильно их различает — запись
`aiRuns` несёт `provider` и `model`.

А `calculateQualityMetrics` считает по всем записям сразу. После слияния двух журналов у каждой
работы окажется четыре прогона — два от одной модели, два от другой, — и метрики смешаются:
среднее отклонение усреднится по обеим моделям, а `stabilityWithinOnePoint` станет и вовсе
бессмысленной, потому что сравнит ответ одной модели с ответом другой и назовёт разброс между
разными моделями нестабильностью одной.

Смешанные метрики выглядят как измерение и измерением не являются. Это худший исход: на них
принимают решение.

## Границы

Входит:

- Ключи `--model=<id>` и `--provider=<имя>` у `scripts/ai-quality-report.js`: метрики считаются
  только по прогонам, совпавшим с фильтром.
- Выбранный фильтр печатается в отчёте рядом с именем набора: по чему считали, должно быть видно
  в самом отчёте, а не только в истории команд.
- **Предупреждение, когда фильтра нет, а моделей в наборе больше одной.** Молча смешать —
  единственный по-настоящему опасный исход, и он должен быть громким.
- Работа, у которой после фильтра не осталось ни одного прогона, называется поимённо: набор,
  измеренный наполовину, не то же самое, что измеренный целиком.
- Без ключей поведение прежнее. `npm run quality:check` и `npm run quality:release` без аргументов
  печатают ровно то же, что и сегодня.

Не входит:

- Изменение формул метрик и порогов §11.3. Тикет меняет, по какому подмножеству считать, а не как.
- Правка набора и журналов. Отчёт только читает.
- Выбор модели за владельца. Задача — дать сравнимые числа, а не назвать победителя.

## Файлы

- `scripts/ai-quality-report.js` — разбор ключей, фильтрация, предупреждение.
- `ai/quality.js` — только если фильтрацию честнее делать там; формулы не трогать.
- `test/quality.test.js` или новый тест — фильтр оставляет только свои прогоны; смешанный набор без
  фильтра даёт предупреждение; работа без прогонов под фильтром названа; без ключей всё как было.
