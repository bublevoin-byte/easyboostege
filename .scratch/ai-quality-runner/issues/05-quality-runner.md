## Что сделать

Появляется команда, которая берёт эталонный набор, прогоняет каждую работу через ту же серверную
операцию, что и приложение, и пишет результат построчно в журнал. Это недостающее звено раздела 11:
метрики уже умеют считаться, эталонные оценки уже собраны, а прогонов ИИ нет ни одного.

```bash
npm run quality:run -- --provider=grok --runs=2
```

## Границы

Входит:

- Скрипт `scripts/ai-quality-run.js`. Ключи: `--provider` (обязательный), `--runs` (по умолчанию 2),
  `--delay` (по умолчанию 2000 мс), `--dataset`, `--out`, `--only=<id>`.
- Для каждой работы с непустым `assignmentData`: сборка входа `{taskType, answer, assignment}`,
  `buildWritingPrompt`, вызов через `ai/provider-client.js`, разбор через
  `parseAndValidateWritingReview` с **одной попыткой восстановления формата** — как в приложении.
  §11.3 считает схему пройденной именно с учётом одной попытки, поэтому факт восстановления
  пишется отдельным полем `repaired`.
- Лимиты `maxTokens` и `timeoutMs` берутся из `ai/operations.js` по имени операции.
- Провайдер закреплён на весь прогон, подмена на запасного выключена. Имя провайдера и модели
  пишется в каждую строку журнала.
- Последовательный вызов с паузой; параллельности нет.
- Запись строки в журнал **сразу после ответа**, до перехода к следующему вызову.
- Возобновление: при повторном запуске с существующим журналом уже сделанные пары
  «работа + номер прогона» пропускаются. Платить дважды за один ответ не нужно.
- Ctrl+C: текущий вызов дописывается, скрипт выходит с кодом 0 и печатает, сколько осталось.
- Прогресс строкой на каждый вызов и итог: число вызовов, токены, оценка стоимости по ценам из
  `config.ai`, сколько работ пропущено и почему.
- Неудачный вызов записывается тоже — с кодом ошибки и сырым ответом. Доля валидных ответов есть
  метрика §11.2, и молча выброшенный провал её подделывает.
- Новый файл добавляется в список `npm run check`.

Не входит:

- Обращения к базе данных. Раннер не открывает соединение, не пишет в `ai_requests` и не
  расходует дневной бюджет учеников: прогон делает владелец, а не ученик.
- Слияние журнала в набор — это тикет 06. Раннер только пишет журнал.
- Запуск настоящего платного прогона. `.env` на машине нет, ключей провайдера нет; запуск —
  действие владельца. В тестах раннер гоняется на подставном провайдере, без сети.
- Устная часть: `speaking-3-fipi.json` прогоняется отдельной работой по тому же образцу.

## Файлы

- `scripts/ai-quality-run.js` — новый: раннер.
- `quality/runs/.gitkeep` — новый: каталог журналов.
- `.gitignore` — журналы прогонов не попадают в репозиторий автоматически; в набор они приезжают
  слиянием, и сырой платный журнал остаётся у владельца.
- `package.json` — команда `quality:run`, новый файл в `check`.
- `test/ai-quality-run.test.js` — новый: два прогона на подставном провайдере дают две строки на
  работу; восстановление формата отмечено `repaired`; невалидный ответ записан, а не выброшен;
  повторный запуск ничего не дублирует; работа без `assignmentData` пропущена с причиной.

## Definition of Done

- [ ] `npm run quality:run -- --provider=<имя> --runs=2` на подставном провайдере даёт журнал с
      двумя строками на каждую готовую работу.
- [ ] В каждой строке есть полный разбор ИИ, провайдер, модель, длительность и расход токенов.
- [ ] Повторный запуск с тем же журналом не делает ни одного лишнего вызова.
- [ ] Прерывание не теряет уже полученные ответы.
- [ ] База данных не участвует: тест проходит без `DATABASE_URL`.
- [ ] `npm test` проходит.
- [ ] `npm run lint` и `npm run check` проходят.
- [ ] Один коммит на тикет.
