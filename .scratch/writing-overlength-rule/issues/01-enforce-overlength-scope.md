# 01 — Проверять только допустимый фрагмент длинной работы

Status: done
Blocked by: —
Spec: .scratch/writing-overlength-rule/spec.md#solution

## Что сделать

Одним вертикальным изменением провести правило превышения объёма через серверную подготовку ответа, вызов ИИ, журнал пользовательской попытки, API и экран результата: длинная работа оценивается только в допустимых первых 140/250 словах, а ученик видит, какая часть учтена.

## Границы

- Входит: единый подсчёт и выделение первых слов, серверный маршрут, версия промпта, файловое и PostgreSQL-хранилища с миграцией, экспорт/удаление, API-документация, экран результата, ТЗ и регрессионные тесты.
- Входит: бесплатный сквозной тест с подставным провайдером, подтверждающий «полный ответ → усечённый запрос → целый балл и предупреждение → сохранённая попытка».
- Не входит: изменение тарифа, открытие анонимного доступа, платные вызовы, сбор новых работ ФИПИ, золотой набор, push и deploy.

## Definition of Done

- [x] Задание 37 не усекается на 154 словах и оценивает только первые 140 слов начиная со 155-го.
- [x] Задание 38 не усекается на 275 словах и оценивает только первые 250 слов начиная с 276-го.
- [x] Провайдер, объективный анализ и замечания не получают текст за пределами оцениваемого фрагмента.
- [x] Успешный API-ответ сообщает полный и оценённый объём, признак усечения и применённый лимит.
- [x] Экран результата при усечении явно сообщает «оценены первые 140/250 слов», не скрывая экспериментальное предупреждение.
- [x] Попытка в файловом и PostgreSQL-хранилище содержит полный `answer` и отдельный `evaluated_answer`; экспорт и удаление остаются корректными, старые записи совместимы.
- [x] Версия промпта и документация происхождения отражают новое поведение.
- [x] ТЗ фиксирует автоматизацию правила, но §11 остаётся незакрытым.
- [x] Целевые тесты, `npm run lint`, `npm run check` и `npm test` проходят без платных ИИ-вызовов.
- [x] Проведён двухосевой review относительно исходного коммита и замечания устранены либо явно обоснованы.
- [x] Один локальный коммит на тикет; рабочее дерево чистое.

## Результат

Сервер и quality-runner используют общий `prepareWritingPrompt`: для задания 37 ответ на 155+
словах ограничивается первыми 140, для задания 38 на 276+ — первыми 250. API возвращает область
оценивания, пользовательская попытка хранит `answer` и `evaluated_answer`, а экран показывает
предупреждение об усечении отдельно от экспериментального disclaimer. Миграция 020 заполняет
новое поле полным ответом для прежних строк. Двухосевой review относительно `4ed11f5` завершён:
дублирование подготовки prompt устранено, сквозные проверки 154/275 добавлены, оставшихся замечаний
нет. Итоговые проверки: lint и check проходят; 407 тестов, 406 проходят, 1 PostgreSQL-тест
штатно пропущен без `TEST_DATABASE_URL`.
